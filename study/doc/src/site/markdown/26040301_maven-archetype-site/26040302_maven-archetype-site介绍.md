# maven-archetype-site 介绍
在 Maven 生态中，**`maven-archetype-site`** 与 **`maven-archetype-site-simple`** 均为**文档站点生成原型**，核心作用是通过标准化结构快速搭建**独立/内嵌的文档站点**（如项目手册、API 说明、构建报表）。两者定位差异在于**复杂度与功能覆盖度**，以下从**效果拆解、结构对比、适用场景**展开深度解答：

---

## 一、核心效果总览
选择这两个 Archetype 后，Maven 会生成**以 `src/site` 为核心的站点目录结构**，配合 `maven-site-plugin` 插件可将 Markdown/XML 文档编译为**静态 HTML 站点**（含导航、样式、报表）。其本质是**“文档编写的脚手架”**，让开发者专注于内容而非结构。


## 二、分原型效果详解
### 1. `maven-archetype-site`：**全功能独立站点原型**
#### 生成结构与效果
- **核心目录**：
  ```text
  ├── src/
  │   └── site/                # 站点内容根目录
  │       ├── apt/              # APT 格式文档（Maven 推荐的轻量标记语言）
  │       ├── fml/              # FML 格式文档（FAQ 专用）
  │       ├── xdoc/             # XDoc 格式文档（传统 XML 标记）
  │       ├── resources/         # 站点资源（图片、CSS、JS）
  │       └── site.xml          # 站点导航配置文件（定义菜单、页面层级）
  ├── pom.xml                   # 含 maven-site-plugin 配置（默认集成报表插件）
  ```
- **功能效果**：
    - 支持**多格式文档混合编写**（APT/XDoc/FML）；
    - 自动集成**Maven 报表插件**（如 `javadoc`、`surefire-report`、`cobertura` 覆盖率报告）；
    - 生成**带左侧导航、顶部面包屑**的完整 HTML 站点（样式基于 Maven 默认皮肤）；
    - 适合**多项目统一文档中心**或**复杂产品手册**（如企业级框架的 API 文档+用户指南）。

#### 示例场景
某开源框架需维护“开发手册+API 文档+贡献指南”，用此原型生成后，可在 `src/site/apt` 写手册、`xdoc` 放 API 说明，`site.xml` 配置“手册→API→贡献”的导航，最终通过 `mvn site` 生成一站式站点。


### 2. `maven-archetype-site-simple`：**轻量单页站点原型**
#### 生成结构与效果
- **核心目录**（比 `site` 精简 50%+）：
  ```text
  ├── src/
  │   └── site/
  │       ├── index.apt         # 唯一文档（APT 格式，单页内容）
  │       └── site.xml          # 极简导航（仅首页）
  ├── pom.xml                   # 仅含基础 maven-site-plugin 配置
  ```
- **功能效果**：
    - 仅支持**单页面文档**（默认用 APT 格式）；
    - 无集成报表插件（需手动添加）；
    - 生成**无复杂导航的简洁 HTML 页**（适合快速说明）；
    - 适合**小型项目的 README 扩展**或**临时文档**（如单次迭代的变更说明）。

#### 示例场景
某工具类库的 1.0 版本发布，需写一个“快速使用指南”，用此原型生成后，直接在 `index.apt` 写步骤，运行 `mvn site` 得到单页 HTML，嵌入 GitHub Pages 即可。


## 三、两者效果对比（表格一目了然）
| **维度**         | `maven-archetype-site`                | `maven-archetype-site-simple`          |
|-------------------|----------------------------------------|------------------------------------------|
| **定位**           | 全功能独立文档站点                      | 轻量单页文档站点                          |
| **目录复杂度**     | 含 `apt/fml/xdoc/resources` 多子目录    | 仅 `index.apt`+`site.xml`                 |
| **文档格式支持**   | APT/XDoc/FML 多格式                     | 仅 APT（单页）                            |
| **报表集成**       | 默认集成 Javadoc、测试报告等插件        | 无（需手动配置）                          |
| **导航能力**       | 多级菜单、面包屑导航                    | 仅单页（无导航）                          |
| **适用场景**       | 多项目文档中心、复杂产品手册            | 小型项目说明、临时变更记录                |


## 四、效果延伸：站点如何“活”起来？
生成结构后，需通过**`maven-site-plugin`** 将内容编译为 HTML，核心步骤：
1. 在 `pom.xml` 中配置插件（以 `site` 为例）：
   ```xml
   <build>
       <plugins>
           <plugin>
               <groupId>org.apache.maven.plugins</groupId>
               <artifactId>maven-site-plugin</artifactId>
               <version>3.12.1</version>
               <configuration>
                   <skin>flatly</skin> <!-- 可选皮肤（如 Bootstrap 风格） -->
               </configuration>
           </plugin>
       </plugins>
   </build>
   ```
2. 编写文档（如 `src/site/apt/index.apt`）：
   ```apt
   ~~ Generated by Maven Site Archetype ~~
   
   = 我的项目文档
   
   == 简介
   这是一个用 Maven Site 生成的文档站点示例。
   
   == 快速开始
   * 克隆仓库：`git clone https://github.com/xxx/xxx.git`
   * 运行：`mvn clean package site`
   ```
3. 执行命令生成站点：`mvn site`，产物位于 `target/site/index.html`。


## 五、视野拓展：站点文档的未来趋势
- **格式迁移**：传统 APT/XDoc 逐渐被 **Asciidoc**（更易读、支持图表）取代，可通过 `asciidoctor-maven-plugin` 替代；
- **静态站点生成器**：更复杂的文档需求（如博客、教程）可选用 **GitBook**、**Docsify**，但仍可复用 `src/site` 结构；
- **自动化集成**：结合 **GitHub Actions**，可实现“提交文档→自动构建→部署到 GitHub Pages”的全流程。


## 总结
选择 `maven-archetype-site` 还是 `site-simple`，本质是**“文档复杂度与维护成本的权衡”**：
- 需**多页面、多格式、带报表**的正式文档 → 选 **`maven-archetype-site`**；
- 仅需**单页快速说明** → 选 **`maven-archetype-site-simple`**。

两者的共同效果是**将“文档编写”与“站点构建”解耦**，让开发者用标准化结构聚焦内容本身。
