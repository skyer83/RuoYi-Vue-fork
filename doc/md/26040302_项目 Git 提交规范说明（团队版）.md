# 项目 Git 提交规范说明（团队版）

---

## 一、提交信息格式规范
所有代码提交必须遵循以下格式：
```
类型: 简要描述（冒号后必须加空格）
```

### 允许的类型
- **feat**: 新增功能、业务模块
- **fix**: 修复 bug、线上问题
- **docs**: 仅修改文档（README、注释、wiki）
- **style**: 代码格式调整（空格、缩进、分号等，不影响逻辑）
- **refactor**: 代码重构（既非新功能，也非修复 bug）
- **test**: 新增/修改单元测试、集成测试
- **chore**: 构建脚本、依赖升级、工具配置等杂项
- **perf**: 性能优化
- **ci**: CI/CD 配置文件修改
- **revert**: 回滚历史提交

### 正确示例
```
feat: 新增用户登录接口
fix: 修复订单列表查询异常
docs: 更新部署文档
refactor: 重构用户中心逻辑
test: 增加支付接口单元测试
chore: 升级 lombok 版本
```

### 错误示例（会被拦截，无法提交）
```
修复bug
新增登录
feat新增功能
fix:修复bug（缺少空格）
修改了一些代码
```

## 二、自动校验配置（Maven 项目）
本项目已内置 Git 提交校验钩子，**无需安装 Node、无需任何插件**。

### 首次拉取代码后执行
执行任意 Maven 构建命令即可自动配置钩子：
```bash
mvn compile
```
或
```bash
mvn install
```

执行后，后续所有 `git commit` 都会自动校验格式，不符合规范将**直接拒绝提交**。

---

## 三、IDEA 使用说明
1. 打开提交窗口：`Ctrl + K`（Windows）/ `Cmd + K`（Mac）
2. 提交信息必须以规范前缀开头
3. 格式错误会直接弹出错误提示，无法提交

---

## 四、常见问题
1. **提交时报错：提交失败！格式不符合规范**
    - 检查是否以 `类型: 描述` 格式书写
    - 检查英文冒号后是否有**一个空格**
    - 检查类型是否在允许列表内

2. **Windows 下钩子不生效**
    - 使用 Git Bash 执行一次 `mvn compile`
    - 或手动执行：
      ```bash
      chmod +x .git/hooks/commit-msg
      ```

3. **如何跳过校验（不推荐）**
   ```bash
   git commit --no-verify -m "xxx"
   ```
   仅用于紧急回滚等特殊场景。
